# 使用、續跑與人工修正

先依 [SETUP.zh-TW.md](SETUP.zh-TW.md) 完成 Python、Ollama 和模型準備，再使用下列入口。已驗證機器與適用範圍見 [HARDWARE.zh-TW.md](HARDWARE.zh-TW.md)。Repository 只提供來源程式；下載 ZIP 後沒有模型和 Python 環境，不能直接開始翻譯。

## 第一次處理資料夾

1. 將同一章的圖片直接放在一個資料夾，例如 `D:\Comics\Chapter01`。只會讀這一層，不會遞迴掃描其他章或中文輸出子資料夾。
2. 雙擊根目錄的 `Start_Manga_Folder_Translator.cmd`。主視窗名稱是「本機漫畫資料夾翻譯」。
3. 按「選擇資料夾…」，選擇直接含圖檔的章節資料夾。畫面應顯示找到的圖片數和輸出位置。
4. 按「開始翻譯」。第一批較小，完成後即可按「開啟中文資料夾」查看已交付圖片；後續批次繼續執行。
5. 結束時同時看「已完成」「待審查」「頁面失敗」和「工作狀態」。完成頁數不代表全部譯意、音效與排版都已人工檢查。

支援 JPG、JPEG、PNG、WebP、BMP、TIF、TIFF、GIF 的單張靜態圖片。動態 GIF、多頁 TIFF 等多格格式會停止匯入，請先拆成單張圖片。PDF、ZIP、CBZ、CBR 不會直接解包或轉頁。檔名採數字自然排序，例如 `2.png` 在 `10.png` 前。

輸入保留原檔。工作副本會依 EXIF 調整方向、透明底合成白底並轉 RGB PNG；因此「原圖未修改」不代表工作副本和原始檔 bytes 相同。輸出統一為 PNG，通常沿用原檔名主體；同名不同格式有避免名稱衝突的處理。

一般閱讀使用中文資料夾內的 PNG。`翻譯對照.csv` 以 UTF-8 BOM 儲存，欄位是「原檔名」「中文圖片」「文字框」「日文」「繁體中文」。`_工作資料` 用於續跑、診斷、審查和可編輯專案；保留整個目錄才能保留這些能力。

「開始翻譯」每次建立新一輪，已存在時使用 `Chapter01(中文)_2`、`_3`。它不表示接續舊工作；接續請使用「續跑上次工作」。不要把中文輸出資料夾再當作新的日文來源選入。

## 停止與續跑

按「停止」會要求工作在可取消的位置結束，並清理它自己建立的模型服務。模型請求、讀寫或子程序收尾可能仍需一段時間，畫面會顯示「停止中，正在結束目前工作並釋放本機模型…」。保留當前視窗等它回到停止／結束狀態；不要以連續開新視窗取代等待。

重新開啟後選擇相同來源資料夾，按「續跑上次工作」。程式選擇最近保存且狀態為失敗、已取消、部分完成或 running 的候選工作；`running` 可能是上次中斷留下的狀態，所以先確認沒有另一個視窗仍在執行。安裝目錄中的檔案鎖也會阻止同時翻譯。

續跑前會重驗來源清單、原圖與工作圖 SHA-256，以及已輸出圖的記錄。原圖新增、改名、重排、修改，或成品被外部編輯／移走時，可能拒絕續跑。保留已有成果並按「開始翻譯」建立新工作。移動整個來源或工作目錄、切換模型、修改關鍵程式後，也不要假定舊工作仍可續跑。

已確認完成的頁不應重新翻譯；未完成的頁可重用經驗證的前處理與完全相符的模型回覆。待審頁不會因按續跑就自動變成通過，需要完成對應審查。

## 待審、失敗與工作錯誤

| 畫面項目 | 代表什麼 | 下一步 |
|---|---|---|
| 待審查 | 有候選預覽，但仍需要人確認，例如頁面行數對不上後做過逐框補救。 | 開啟審查視窗，逐框對照原文和圖片。 |
| 頁面失敗 | 某頁翻譯或頁面處理失敗，其餘頁可能仍成功。 | 在明細中查看原因；修正環境問題後續跑。 |
| 工作錯誤 | 排程、保存檔案、發布或收尾等工作層級錯誤。 | 按「查看／複製診斷…」，不要把它當成最後一頁模型翻譯錯誤。 |
| 版面／小字提示 | 偵測到可能需要查看的版面問題。 | 打開成圖人工確認；目前不是所有警告都會阻擋輸出。 |

主視窗可以勾「顯示詳細紀錄」，按「開啟工作紀錄」，或雙擊「待審查與失敗明細」的項目。在「待審查、失敗與工作診斷」視窗可使用「開啟原圖」「開啟該項紀錄」「開啟相關日誌」「複製此項診斷」「複製全部診斷」「重新讀取紀錄」和「左右對照審查…」。

複製出的診斷可能包含本機路徑和作品文字。提交 GitHub issue 前先刪除這些內容，保留錯誤類型、發生階段、套件版本與可用合成資料重現的步驟。

## 逐框審查

有待審頁時，主視窗按「開啟審查視窗…」。工作臺標題為「人工審查與單頁視覺精修工作臺」，左邊是「原始日文圖」，右邊是「中文即時預覽圖（所見即所得）」。下方列出「編號」「原始日文」「繁體中文」。

1. 從上方選擇頁面，點選圖中的文字框或表格列。
2. 用「放大目前框 (F)」檢查原文、譯意、說話者上下文、文字是否溢出，以及抹字是否傷圖。用「完整頁面 (A)」回看整頁。
3. 確定該框的既有預覽可以接受，按「本框通過 (Space)」。確認進度會保存，不必一次完成全部框。
4. 只有所有框都確認後才輸出待審頁；已整頁查看過也可按「整頁通過並輸出 (Ctrl+Enter)」。完成後工作臺會移到下一待審頁。

「本框通過」表示你接受這個候選，不會再呼叫模型改譯文。剩最後一框時，按鈕文字可能改為「本框通過並輸出」。若確認已完成但寫檔未完成，可能顯示「重試輸出本頁」。預覽或綁定檔案已更動時，先重新開啟並確認最新內容，不要直接沿用舊核准。

## 單頁文字與排版精修

沒有待審頁、但已有成品時，主按鈕會顯示「單頁視覺精修工作臺…」。它可用現有工作資料重繪已翻譯頁，不需要重新跑整本模型。

選取文字框後，在「繁體中文內容（支援手動 Enter 換行）」修改文字；也可使用「A- 縮小字體」「A+ 放大字體」「直排/橫排切換」「框擴大 (+15%)」「框收縮 (-15%)」「重設本框」。右側預覽會立即重繪。按「儲存並發布本頁修改 (Ctrl+S)」才保存 overrides 並覆寫該頁輸出圖。

公開版只允許精修已發布的頁：工作須已結束執行，該頁須有唯一的檔名對照、現有成品和記錄雜湊一致，而且沒有該頁的失敗／待審狀態。工作即使整體只有部分完成，符合上述條件的成功頁仍可精修。未發布或仍待審時保存按鈕停用，直接按 Ctrl+S 也會被檢查拒絕。成品被外部修改時，先保留修改內容，不能以此入口強行覆蓋。

**目前精修保存有已知限制。** 這條路徑依序寫入覆寫設定、PNG、`file-map.json`，不具有整組原子交易；它也不會同步更新 `翻譯對照.csv`、批次 `translations.json`、verification 或既有審查收據。文字改完後，CSV 仍可能顯示原機器翻譯。建議在已完成工作上精修，先保留原成品副本；精修後逐張核對，不要把舊 CSV 當成已同步的精修稿。

Ctrl+S 不能取代待審確認。先按前述流程核准既有候選並完成發布，再對已發布頁保存精修，並再次查看最終 PNG；現有批次審查證據仍記錄原候選預覽，不能當作精修後畫面的全新核准。需要嚴格圖文一致的交付時，請人工核對並另行整理最終翻譯對照。也不要假定之後續跑或重發批次會完整保留人工精修。

若你在待審視窗已做文字／排版調整，「整頁通過」會先走原有審查發布流程，成功後再嘗試套用該頁調整。兩步分別可能失敗；原候選已輸出而精修未寫入時，以錯誤訊息及實際 PNG 為準。

## 音效審查入口

「套用音效審查…」讀取的是針對同一工作建立並確認過的 JSON 決策。它可以將指定音效區域局部還原成原圖，不會重新翻譯整頁；程式核對來源、預覽、文字框、issue ID 和允許修改區域，並檢查區域外像素。

這不是一般任意 JSON 匯入器，也不會從原圖自動替人作音效判斷。手上沒有與該工作綁定的決策檔時，使用前面的左右對照與單頁精修，不要手工猜一組路徑或雜湊來繞過檢查。

## 常見問題

| 現象 | 已知原因與處理方向 |
|---|---|
| 雙擊啟動器沒有視窗 | 先從 PowerShell 執行安裝文件的檢查入口，確認專用 Python、PyQt6 和相依套件已準備；隱藏視窗入口不適合讀取啟動錯誤。 |
| 第一層沒有圖片，但有子資料夾 | 改選真正放圖片的章節資料夾；程式不遞迴處理。 |
| Ollama 或模型不存在／識別不符 | 按安裝文件準備固定版本模型和此專案的 model store。只安裝另一個 Ollama 模型名稱還不夠；不要刪除身分驗證程式來強行續跑。 |
| `11436` 已被佔用／服務無法啟動 | 資料夾批次會改選空閒 loopback 埠，並核對 listener PID，不接管未知程序。若仍失敗，查看服務日誌與殘留工作。直接開 BallonsTranslator 的啟動器仍使用固定 `11436`，其錯誤需另外檢查該埠服務。 |
| 記憶體不足、載入／卸載頻繁 | 關閉其他大型模型及高記憶體應用，等待可用記憶體回升；本程式的記憶體門檻不代表任何 8 GB／16 GB 機器都能跑這組 14B 模型。 |
| 回覆完成但行數不符 | 合適情況下會逐框補救並列待審；仍失敗時保留證據，先查看頁面錯誤，不要手動把失敗狀態改成完成。 |
| 看見日文原圖或少頁 | 檢查待審與失敗數；工作區保存原圖供恢復，不代表已翻譯。先以中文輸出資料夾及完成紀錄核對。 |
| 原圖／成品已更動，無法續跑 | 保留改過的檔案，建立新工作。此保護是避免把舊結果與新來源混用。 |
| JSON／CSV 寫入被拒絕或檔案遭佔用 | 關閉正在佔用該檔的編輯器、Excel 或同步操作後再重試。系統只有限次重試，不會無限等待。保留工作目錄，依診斷確認已交付哪些頁。 |
| 字體缺字、排版不同 | 確認 Windows 中文字型可用；模型相同不保證不同字型或 Qt 版本得到同樣排版。 |
| 精修後 CSV 沒變 | 現有精修保存不會同步 CSV，屬上述已知限制。以精修圖、overrides 和人工整理的最終對照核實。 |

## 完成後如何保存

要保留續跑、審查與精修能力，將輸出資料夾連同 `_工作資料` 一起備份。只需要閱讀時可另複製 PNG；不要把這份閱讀副本當作可續跑工作。原圖、工作圖和譯文均可能屬私人內容，本 repository 的忽略規則不能保護你手動貼進 issue、其他 repository 或雲端分享的檔案。

目前對這些流程的結構性驗證詳見 [ARCHITECTURE.zh-TW.md](ARCHITECTURE.zh-TW.md)。自動完成與人工品質確認是不同件事，正式分享成品前仍應查看每頁。
